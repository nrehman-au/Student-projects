Selection guidance

Choosing a manageable project and planning a fair comparison

Choose a level

Eight standard projects support Bachelor work: 2.1–2.5, 3.1, 3.3 and 4.1. Projects 2.4 and 3.1 are Bachelor-only; the others also offer a Master extension. In Project 4.1, choose either industrial inspection or medical segmentation.

Projects 3.2, 3.4, 3.6 and 3.7 prefer Master students, with reduced Bachelor versions when a prepared data pipeline or fixed comparison is available. Projects 3.5, 4.3 and 5.1 are Master-only.

The three industry projects in Category 1 prefer Master students. A reduced Bachelor version depends on the partner supplying prepared data and an agreed task.

Choose a topic

  1. Start with an application you find interesting, such as traffic, health, industrial monitoring or recommendation.
  2. Read the goal and choose one focused question you want to answer.
  3. Check access to the data, model weights and starting code.
  4. Run a simple reference method before planning an extension.
  5. Agree the scope and computing needs with the supervisor.

Bachelor work can make a useful contribution through a careful comparison and a clear explanation of the results. Master work should investigate an extension, such as improved robustness, transfer to new conditions or a new representation. An unchanged run of a published method is a starting point for either route.

Data and model access

The project links point to the dataset providers and reference implementations. Public access to a page or repository does not guarantee permission to redistribute its data or model weights. Check the terms on the linked source before using or sharing a resource.

  • Industry data: Siemens Gamesa and Tetra Pak data are supplied under an agreed access arrangement.
  • Medical data: Check registration and use conditions for AMOS22, M&Ms and ACDC. PTB-XL provides its access conditions on PhysioNet.
  • DINO models: DINOv2 has publicly available weights. DINOv3 model weights require an access request and acceptance of the model terms.
  • HEAPO: The linked Zenodo dataset is released under CC BY 4.0; credit its authors. Check the number of usable household labels before choosing the task.
  • Starting repositories: Check the supported software versions and any licence before adapting code. A repository link is a reference, not a guarantee that the code will run unchanged in a current environment.

Plan a fair evaluation

Use the same data and evaluation setup for the methods you compare. Keep all related recordings from one person, patient, household, engine, bearing or process cycle together. For forecasting, use earlier data for training and later data for evaluation.

Use validation data to choose model settings and keep the final test set separate. Measure the outcome that matches your goal, and explain where the method works well or fails. A result showing no improvement is valuable when the comparison is fair and the explanation is supported by evidence.

Start with one application, one dataset and a small set of methods. Add further experiments only after the first comparison works.
