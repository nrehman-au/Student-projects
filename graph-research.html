Category 3 Implementing modern Graph ML research

Reproducing an anchor paper and testing a focused extension

Modern Graph ML extends the basic GNN idea to settings where ordinary neighbourhood aggregation is not enough. In a spatiotemporal graph, both node measurements and their relationships may change over time; a dynamic graph can gain or lose nodes and edges; a graph Transformer uses attention to capture longer-range interactions; and graph self-supervision learns representations before task labels are introduced. Graph retrieval can also select a relevant subgraph before an LLM answers a question.

These projects focus on the research method rather than only the application. Each begins from an anchor paper with public code and a public benchmark. The first milestone is to understand and reproduce its central mechanism under the stated protocol. For example, a student might reproduce a traffic Transformer and then ask how it should represent a sensor that was absent during training, or reproduce graph contrastive learning and then test which structural properties an augmentation should preserve.

For a Bachelor project, a careful reproduction and focused comparison can be sufficient. A Master project must add a clear, testable question through a new mechanism, a stricter evaluation setting or a detailed robustness analysis. Moving unchanged code to another dataset or tuning hyperparameters alone is not the research contribution.

From repository to research question

Installing code, reproducing a table, tuning hyperparameters or applying an unchanged model to another dataset is a starting point, not an MSc contribution. The proposed contributions here concern sensor representations, induction protocols, graph augmentations, compute routing and retrieval budgets.

Learn first and find ideas

  • Spatiotemporal graphs: survey, DCRNN, STAEformer. Dynamic graphs: TGN and DyGFormer.
  • Graph Transformers: Graphormer, GraphGPS. Self-supervision: DGI, GRACE, GraphCL, GraphMAE. Graph RAG: G-Retriever.
  • Stanford introductions: Self-Supervised Learning for Graphs, contrastive molecular pretraining, RingSAGE and Graph Transformers for TSP.

3.1 Inductive sensor embeddings for STAEformer

TaskNode-level multi-horizon regression Recommended levelMSc preferred; BSc reproduction variant ComputeModerate; 4–8 GB GPU Starting paperLiu et al., STAEformer, CIKM 2023

What you will do. STAEformer learns a separate adaptive representation for each sensor and input time position. The sensor-specific representation cannot directly handle a sensor that was absent during training. This project develops an embedding generated from the new sensor’s graph context and short calibration history.

Project goal. Preserve ordinary forecasting accuracy while improving forecasts for sensors deliberately held out of training.

Data. Use PEMS04, supplied by the official STAEformer repository: 307 sensors and 16,992 five-minute observations, with the official chronological split and 12-step input/output. PEMS08 is optional confirmation.

Methods and starting code. Compact STAEformer, vanilla Transformer, GRU and STGCN/DCRNN. Replace or complement the free sensor-indexed embedding with a shared encoder using calibration summaries, graph statistics and positional encodings.

Required baselines. Original STAEformer, mean/zero/random embeddings for unseen sensors, the proposed inductive encoder and a hybrid seen-sensor model. Reproduce the adaptive-embedding benefit before changing the method.

Evaluation. Report standard forecasting and seeded 10/20/30% sensor cold-start settings. Remove held-out sensors and incident correlation edges during training, then expose only 1, 3 or 7 days of unlabelled calibration history. MAE is primary; report RMSE/MAPE by horizon and separately for seen/unseen sensors, plus at least three seeds.

Bachelor scope. Reproduce compact STAEformer on PEMS04 and its embedding ablation. Random sensor masking may be explored, but no new inductive encoder is required.

Master research question and contribution. Research question: Can a graph-conditioned shared sensor encoder recover useful representations for newly installed sensors without harming the fixed-network model? The contribution is the encoder, a leakage-safe cold-start protocol and analysis by degree, correlation strength and calibration length. If it fails, quantify when sensor-specific parameters are indispensable.

Practical notes. Public data and official code reduce setup work. Keep the unseen-sensor protocol separate from Project 1.2: that project learns changing edges, while this project represents nodes that were absent during training.

3.2 Inductive evaluation of GRACE

TaskSelf-supervised node representation learning then node classification Recommended levelBSc or MSc ComputeVery light; CPU or low-memory GPU Starting paperZhu et al., GRACE, 2020

What you will do. GRACE makes two corrupted views of a citation graph agree. Standard evaluation is transductive: features and edges of test nodes can be visible during self-supervised pretraining. This project measures how much that access matters and develops a local variant for genuinely unseen nodes.

Project goal. Separate representation quality from the advantage of seeing the evaluation graph during pretraining.

Data. Use Cora and CiteSeer, with PubMed optional, through the PyG Planetoid loader. The downstream task predicts a paper topic for each node.

Methods and starting code. Implement GRACE edge removal, feature masking, shared GCN encoder, projection head and node contrastive loss. Start from the official GRACE repository. Compare Deep Graph Infomax, a feature-only MLP, GraphSAGE and a supervised GCN.

Required baselines. Random frozen encoder, GRACE frozen probe, GRACE fine-tuning and the same encoder fully supervised. Standard transductive and strict inductive pretraining must be separately labelled.

Evaluation. Accuracy and macro-F1 at 1/5/10/100% label budgets. Use at least ten seeded splits with confidence intervals. In strict induction, remove validation/test nodes and incident edges until evaluation, then use the same inference-time neighbourhood policy for all methods.

Bachelor scope. Reproduce transductive GRACE on Cora plus a second dataset, compare frozen, fine-tuned and supervised GCN, and plot label efficiency.

Master research question and contribution. Research question: How much of GRACE’s label efficiency survives strict induction, and can contrastive pretraining on sampled ego-graphs recover the loss? Build a GraphSAGE-style local encoder and analyse performance by held-out node degree, homophily and neighbourhood size. The leakage-controlled benchmark is itself part of the contribution.

Practical notes. Small datasets make multi-seed evaluation realistic. Never place transductive and inductive figures in one undifferentiated leaderboard.

3.3 Structure-aware augmentations for graph contrastive learning

TaskSelf-supervised graph representation learning then graph classification Recommended levelBSc reproduction; MSc method project ComputeLight to moderate; CPU or low-memory GPU Starting paperYou et al., GraphCL, NeurIPS 2020

What you will do. GraphCL learns by making two augmented versions of the same graph agree. Random deletion can destroy bridges, cycles or community structure and accidentally change the graph’s meaning. This project controls that damage rather than merely tuning an augmentation rate.

Project goal. Test whether structure-aware views are more label-efficient and less sensitive to augmentation strength than uniformly random views at the same number of edits.

Data. Use NCI1 (4,110 graphs) and PROTEINS (1,113) from TU Dortmund via the PyG TUDataset loader. Cora/CiteSeer are optional only for a node-level spectral extension.

Methods and starting code. Start with the official GraphCL repository and a GIN encoder. Compare GraphMAE, and optionally GRACE/BGRL for node experiments. Core MSc mechanism: preserve combinatorial structure using bridges, articulation points, cycles or connected components. Stretch mechanism: protect a low-frequency Laplacian band; compare with GCL-SPAN.

Required baselines. Original random GraphCL augmentations at matched edit counts, random frozen GIN, fully supervised GIN and GraphMAE. Pretrain inside each training fold for the strict protocol.

Evaluation. Accuracy and macro-F1 with confidence intervals; frozen probe and fine-tuning at 10/25/100% labels. Also report component-count change, cycle-rank change, degree-distribution distance and, for the spectral route, protected-band distance. Test edit rates such as 5/10/20/30%.

Bachelor scope. Reproduce GraphCL on NCI1, compare its four augmentations and evaluate frozen, fine-tuned and supervised GIN on identical splits. Protecting articulation points only is an optional extension.

Master research question and contribution. Research question: At matched edit budgets, which measurable notion of structural damage best predicts downstream representation failure? The minimum MSc contribution is one defensible structure-aware operator plus matched-budget analysis. A full combinatorial-versus-spectral comparison is an optional 30-ECTS extension. If accuracy does not improve, explain when preservation makes the two views too similar to provide contrastive signal.

Practical notes. Exact spectral work is feasible on these small graphs. Do not begin with ogbn-arxiv; scalable eigenspectrum approximation is a separate advanced problem. Label transductive test-graph exposure explicitly.

3.4 Compute-aware routing between GraphGPS branches

TaskGraph regression Recommended levelBSc reproduction; MSc preferred ComputeLight to moderate; 8 GB GPU preferred Starting paperRampášek et al., GraphGPS, NeurIPS 2022

What you will do. A GraphGPS layer computes both local message passing and global attention for every graph. This project asks whether a small gate can learn when global attention is worth its cost.

Project goal. Find an accuracy–efficiency trade-off and determine whether graphs with stronger long-range structure use the global branch more often.

Data. Use the 12,000-graph ZINC subset from the PyG ZINC loader. Confirm only the selected final settings on Peptides-struct through the PyG LRGB loader.

Methods and starting code. Start from the official GraphGPS repository. Implement a positional/structural encoding, local GINE or GatedGCN, and global Transformer or Performer. Add a soft gate during training and an optional budgeted hard gate at inference.

Required baselines. Local-only, global-only, standard GPS and a fixed scalar mixture, followed by learned soft and hard gates. Keep depth, width and parameters approximately matched.

Evaluation. MAE with at least three seeds. Report trainable parameters, estimated FLOPs, peak memory and measured latency at a fixed batch size. Plot the accuracy–compute Pareto curve and stratify by graph size and a long-range proxy.

Bachelor scope. Implement a compact GPS layer on ZINC and reproduce local-only, global-only and combined branches with one positional encoding.

Master research question and contribution. Research question: Can graph- or layer-conditioned routing reduce global-attention computation while retaining GraphGPS accuracy, and are gate decisions structurally interpretable? Compare multiple compute penalties and test whether simple size/diameter/positional statistics predict routing. The contribution is the router and controlled Pareto analysis, not another GraphGPS run.

Practical notes. ZINC is light. Restrict Peptides-struct to the selected final settings. FLOPs and wall-clock latency answer different questions; report both.

3.5 Question-adaptive retrieval budgets for G-Retriever

TaskQuery-conditioned evidence retrieval and answer ranking Recommended levelAdvanced MSc optional; BSc retrieval-only variant ComputeModerate; no 7B model training required Starting paperHe et al., G-Retriever, NeurIPS 2024

What you will do. G-Retriever scores graph elements, selects a compact connected evidence subgraph and then uses it for question answering. A single global retrieval size trades answer recall against irrelevant context. This project predicts the budget separately for each question.

Project goal. Retrieve substantially smaller evidence subgraphs without reducing answer-entity recall and ranking quality.

Data. Use WebQSP, 4,737 questions, through the PyG WebQSP loader and preprocessing in the official G-Retriever repository. A 1,000–2,000-question subset is acceptable for development; use the official split for final MSc reporting if feasible.

Methods and starting code. Reproduce graph-element scoring and PCST or a documented connected approximation. Compare one-hop, text-similarity top-k, personalized PageRank and fixed PCST budgets. Predict k from non-leaking query, seed-entity and relevance-score features. A language generator is optional.

Required baselines. Fixed k in {3,5,10,20}, a simple validation heuristic, non-connected top-k and an oracle budget used only for analysis. The required downstream task is answer-entity ranking, not full Llama 2–7B reproduction.

Evaluation. Answer-entity recall, Hits@1 or answer F1, retrieved node/edge count and latency. Plot the full quality–size Pareto curve, stratify by path length and question complexity, and test 5/10/20% candidate-edge deletion.

Bachelor scope. Implement retrieval and answer ranking and compare one-hop, text-only, PageRank and fixed-budget PCST. No LLM fine-tuning.

Master research question and contribution. Research question: Can query- and retrieval-confidence features choose the smallest adequate connected subgraph per question? Train a budget selector only on training/validation questions and analyse its calibration and failure modes. A negative result should identify which observable features predict retrieval difficulty.

Practical notes. This project has substantial preprocessing and retrieval-engineering work. It is suitable for a student who specifically wants graph RAG and is comfortable debugging data pipelines. Cache text embeddings and avoid paid APIs or 7B+ fine-tuning.
