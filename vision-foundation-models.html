Category 4 Deep-learning vision models and applications

DINO adaptation with application choices, and federated medical-image denoising

A vision foundation model learns useful image features from a large image collection. These features can be reused for specialised tasks without training a foundation model from scratch.

Choose between adapting DINO for industrial inspection or medical segmentation, and a separate Master project on federated image denoising. In the DINO project, choose one application. The denoising project uses image-restoration networks such as U-Net.

4.1 Adapting DINO vision models for specialised image analysis

LevelBSc or MSc ComputingA GPU is recommended; medical-image preparation and adaptation need more resources.

Goal

Investigate how well a pretrained DINO model works on a specialised image task, and whether adapting it improves accuracy and reliability. Choose one application below; students are not expected to complete both.

Data and starting material

  • Industrial inspection: Detect and locate defects in product images using MVTec AD. Learn from defect-free training images and evaluate on unseen normal and defective images.
  • Medical imaging: Identify abdominal organs in CT scans using the CT portion of AMOS22. Learn from scans with labelled organ boundaries and keep patients separate between training and evaluation.

Starting resources for the selected application:

  • AnomalyDINO paper and DINOv2 detection code.
  • DINOv3 model access and code.
  • MedDINOv3 medical-segmentation example.

Methods and evaluation

Start by using DINO’s pretrained features without changing the backbone. For the Master route, explore a suitable adaptation method, such as training small additional modules or fine-tuning selected layers. Choose the task-specific detector or segmentation decoder for the selected application.

Compare performance on unseen images with a conventional reference method and, for the Master route, before and after adaptation. Investigate how changes in lighting or image quality affect detection or segmentation, using measures appropriate to the chosen task.

Bachelor focus. Study the pretrained features on one application and identify where they work well or fail. Train only the task-specific decoder when segmentation requires it.

Master extension. Investigate whether adaptation improves robustness on the chosen application, and assess the improvement relative to its computational cost.

Practical note. Begin with the backbone used by the selected reference implementation. Confirm dataset access and model-weight access before allocation; DINOv3 weights require access approval and acceptance of the model terms.

4.3 Federated learning for medical-image denoising

LevelMSc only ComputingA GPU is recommended; simulated clients can be trained sequentially.

Goal

Simulate hospitals that improve MRI image quality while keeping their local scans separate. Investigate whether sharing model predictions on a common image set can train a useful global denoising model without sending local scans or model weights to a central server.

Data and starting material

Use M&Ms cardiac MRI to form simulated clients based on scanner vendor, and ACDC as a shared reference-image set. Add controlled synthetic noise and use the original images as reconstruction targets.

  • Federated distillation reference code (FedDF).
  • Flower federated-learning framework.

Methods and evaluation

Explore image-restoration networks such as U-Net, federated learning and knowledge distillation, which trains a student model from other models’ predictions. Adapt prediction sharing to image denoising and compare it with local training and federated weight sharing.

Evaluate image quality on patients kept separate from training, including different scanner vendors or noise conditions. Compare denoising performance and communication cost; conclusions concern removal of the added noise.

Master extension. Can prediction sharing produce a denoising model that works across scanner domains? Study one factor, such as the shared-image set size or differences between client models.

Practical note. Confirm dataset access conditions before allocation. Prediction sharing alone does not provide a formal privacy guarantee.
